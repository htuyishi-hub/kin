# Kin

A trusted introduction network for Rwandan singles — not a swipe app. An introduction network backed by community vouches.

## Run & Operate

- `pnpm --filter @workspace/api-server run dev` — run the API server (port 8080, exposed at `/api`)
- `pnpm --filter @workspace/kin run dev` — run the Expo app (via workflow `artifacts/kin: expo`)
- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from the OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- Required env: `DATABASE_URL` — Postgres connection string, `SESSION_SECRET` — JWT signing secret

## Stack

- pnpm workspaces, Node.js 24, TypeScript 5.9
- API: Express 5
- DB: PostgreSQL + Drizzle ORM
- Validation: Zod (`zod/v4`), `drizzle-zod`
- API codegen: Orval (from OpenAPI spec)
- Build: esbuild (CJS bundle)
- Mobile: Expo 54 + Expo Router 6 + React Native 0.81

## Where things live

- `artifacts/api-server/src/routes/` — all API routes (auth, me, photos, prompts, vouches, matches, messages, etc.)
- `artifacts/kin/app/` — Expo Router screens
  - `(onboarding)/` — welcome → phone → otp → personal → occupation → vouch → prompts → waiting
  - `(tabs)/` — Discover (index), Matches, Profile
  - `match/[matchId].tsx` — chat screen with 3-phase conversation
  - `vouches.tsx` — incoming vouch requests
- `artifacts/kin/contexts/AuthContext.tsx` — JWT token management + AsyncStorage
- `artifacts/kin/constants/colors.ts` — Kin brand design tokens (terracotta #C05A30, warm ivory #FAF4ED)
- `lib/db/src/schema.ts` — source of truth for DB schema (13 tables)
- `lib/api-spec/openapi.yaml` — OpenAPI spec (source of truth for API contract)
- `lib/api-client-react/src/generated/` — generated hooks + Zod schemas (run codegen to regenerate)

## Architecture decisions

- **Contract-first API**: OpenAPI spec → Orval codegen → typed hooks used everywhere on mobile.
- **Invisible tier segmentation**: Student→Tier1, Employed/Business→Tier2, Other/Searching→Tier3. No UI shows this.
- **Double-blind matching**: Both users must express interest before an introduction is made. No one-sided visibility.
- **3-phase structured conversation**: Phase 1 (Values) → Phase 2 (Vision) → Phase 3 (Free). First message assigned to one user by the system.
- **Vouch network**: Requires 2 confirmed vouches before entering the match pool. Vouches are from known community members.
- **72hr expiry**: All matches expire after 72 hours unless smart-close is triggered.

## Product

Kin routes eligible Rwandan singles through a community-vouched onboarding, places them in a milieu-scored match pool, creates double-blind introductions, and guides them through a structured 3-phase conversation before a smart close.

## Gotchas

- Dev OTP bypass: any phone number + code "123456" works in non-production mode.
- `setBaseUrl` must be called at module level in `_layout.tsx`, not inside a component.
- Orval-generated hooks with React Query v5 require `as any` cast on inline query options (queryKey is auto-generated by the hook).
- `OnboardingRequest` does not include `city` — city is stored separately. `fullName`/`gender`/`dateOfBirth` are required in the body even though already saved via `PATCH /me`.
- Pass `dateOfBirth` and `gender` as route params from personal → occupation screen (not available on `MyProfile` type).
- API server listens on port 8080, exposed at path `/api`.
